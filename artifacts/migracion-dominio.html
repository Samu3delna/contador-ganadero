1
Fase 1 · DNS y Cloudflare Dashboard 🌐 DNS / Cloudflare
1.1
Registrar / verificar que eres dueño de contadorganadero.com
Registrador de dominio (ej. Namecheap, GoDaddy, Cloudflare Registrar)

Si aún no has comprado el dominio, adquiérelo. Si ya lo tienes, confirma que esté activo en tu panel.

⚠️
Recomendación: también compra contadorganandero.com (el actual con "n") si no lo tienes, para hacer un redirect 301 y no perder tráfico existente.
1.2
Añadir contadorganadero.com a tu zona en Cloudflare
Cloudflare Dashboard → Add a Site

En el panel de Cloudflare:

  1. Clic en Add a site → escribe contadorganadero.com
  2. Elige el plan (Free es suficiente para empezar)
  3. Cloudflare te dará dos nameservers. Apunta los nameservers del dominio a Cloudflare desde tu registrador
  4. Espera la confirmación de Cloudflare (puede tardar hasta 24h)
1.3
Crear registros DNS en la nueva zona
Cloudflare Dashboard → DNS de contadorganadero.com

Crea los siguientes registros en la nueva zona:

TipoNombreContenidoProxyPara qué sirve
CNAME @ (raíz) contador-ganadero.pages.dev o el dominio Workers ✅ Proxied Frontend (Cloudflare Workers Assets)
CNAME www contadorganadero.com ✅ Proxied Redirect www → apex
CNAME api (opcional) contador-ganadero.onrender.com ⬛ DNS only Subdominio api (si lo usas)
MX @ Configurado por Cloudflare Email Routing — Recepción de correos @contadorganadero.com
ℹ️
El registro MX lo gestiona automáticamente Cloudflare al activar Email Routing en la siguiente fase. No lo agregues manualmente.
1.4
Vincular el dominio personalizado al Worker del frontend
Cloudflare Dashboard → Workers & Pages → contador-ganadero → Custom Domains

El Worker contador-ganadero (definido en frontend/wrangler.jsonc) necesita un dominio personalizado:

  1. Entra al Worker contador-ganadero en el dashboard
  2. Ve a Settings → Domains & Routes
  3. Clic en Add Custom Domain
  4. Escribe contadorganadero.com
  5. Repite para www.contadorganadero.com
✅
Alternativamente, agrega la propiedad "routes" en frontend/wrangler.jsonc antes del próximo deploy.
// frontend/wrangler.jsonc
+  "routes": [
+    { "pattern": "contadorganadero.com/*", "zone_name": "contadorganadero.com" },
+    { "pattern": "www.contadorganadero.com/*", "zone_name": "contadorganadero.com" }
+  ],
1.5
Configurar redirect 301 del dominio viejo al nuevo
Cloudflare Dashboard → zona de contadorganandero.com → Redirect Rules

Para no perder SEO ni tráfico existente, crea una regla de redirect en la zona antigua:

  • Entra a la zona de contadorganandero.com
  • Ve a Rules → Redirect Rules → Create Rule
  • Condición: Hostname equals contadorganandero.com (o wildcard *.contadorganandero.com)
  • Acción: Dynamic redirect → https://contadorganadero.com${uri.path} → Tipo 301
2
Fase 2 · Cloudflare Email Routing + Email Worker 🔶 Cloudflare Workers
2.1
Activar Email Routing en la nueva zona
Cloudflare Dashboard → zona de contadorganadero.com → Email Routing
  1. En la nueva zona contadorganadero.com, ve a Email → Email Routing
  2. Clic en Get Started y sigue el asistente
  3. Cloudflare agregará automáticamente los registros MX y TXT necesarios
  4. Activa el Catch-all → acción: Send to Worker
2.2
Actualizar wrangler.jsonc del Email Worker
cloudflare-email-worker/wrangler.jsonc

Cambia el campo addresses del catch-all:

// cloudflare-email-worker/wrangler.jsonc
-  "send_email": [{ "name": "SEND_EMAIL" }],
-  "email": { "addresses": ["*@contadorganandero.com"] }
+  "send_email": [{ "name": "SEND_EMAIL" }],
+  "email": { "addresses": ["*@contadorganadero.com"] }

Luego redesplega el Worker:

cd cloudflare-email-worker
npm run deploy:email-worker
# o bien:
npx wrangler deploy --config wrangler.jsonc
⚠️
Recuerda que el secreto EMAIL_WEBHOOK_SECRET ya debe estar configurado en Wrangler. Si no, ejecuta:
npx wrangler secret put EMAIL_WEBHOOK_SECRET
2.3
Actualizar el catch-all en el dashboard de Email Routing
Cloudflare Dashboard → Email → Email Routing → contadorganadero.com

En la nueva zona, verifica que el Catch-all address esté apuntando al Worker correcto:

  • Acción: Send to Worker
  • Worker: contador-ganadero-email-worker (el nombre de tu email worker)
3
Fase 3 · Variables de entorno en Render 🟣 Render
🚨
Esta es la fase más crítica. Si CORS no apunta al nuevo dominio, el 100% del tráfico del frontend será bloqueado (login, dashboard, API).
3.1
Actualizar variables en el servicio API Web Service
Render Dashboard → contador-ganadero-api → Environment

Actualiza o agrega las siguientes variables de entorno:

VariableValor nuevoNotas
FRONTEND_URL https://contadorganadero.com CORS principal. Quitar la "/" al final.
CORS_ORIGINS https://contadorganadero.com,https://www.contadorganadero.com Lista separada por comas. Incluir www.
PUBLIC_SITE_URL https://contadorganadero.com Usado en eliminación de datos y emails.
SOCKET_IO_CORS https://contadorganadero.com Si usas Socket.IO
CLOUDFLARE_EMAIL_FROM soporte@contadorganadero.com Correo desde el que envía notificaciones
DOMAIN contadorganadero.com Si está definido como variable separada

Después de guardar, Render reiniciará el servicio automáticamente.

3.2
Actualizar variables en el Background Worker
Render Dashboard → contador-ganadero-imap-worker → Environment

El worker de IMAP/Hacienda también usa FRONTEND_URL para construir links en emails. Aplica las mismas variables que en el paso 3.1.

3.3
Actualizar el archivo .env local (desarrollo)
Raíz del proyecto → .env
-FRONTEND_URL=https://contadorganandero.com/
+FRONTEND_URL=https://contadorganadero.com
+CORS_ORIGINS=https://contadorganadero.com,https://www.contadorganadero.com
+PUBLIC_SITE_URL=https://contadorganadero.com
+CLOUDFLARE_EMAIL_FROM=soporte@contadorganadero.com
ℹ️
En desarrollo puedes dejar VITE_API_URL=http://localhost:5000/api tal como está.
3.4
Google Auth: actualizar Authorized Redirect URIs
Google Cloud Console → APIs & Services → Credentials

El login con Google redirige a FRONTEND_URL/auth/google/callback. Agrega las URIs del nuevo dominio:

  • Authorized JavaScript origins: https://contadorganadero.com
  • Authorized redirect URIs:
    https://contador-ganadero.onrender.com/api/auth/google/callback (ya existe)
    Verifica que el backend en Render también sea accesible desde el nuevo dominio

Fase 5 · Meta (WhatsApp Cloud API) 🟡 Meta Business
5.1
Actualizar la URL de Callback de Eliminación de Datos
Meta for Developers → Tu App → WhatsApp → Configuration
  1. Ve a developers.facebook.com
  2. Selecciona tu app → App Settings → Advanced
  3. En Data Deletion Request URL, actualiza a:
    https://contadorganadero.com/api/webhooks/whatsapp/data-deletion
  4. En User Data Deletion, actualiza la URL de confirmación a:
    https://contadorganadero.com/eliminacion-datos
5.2
Actualizar Webhook URL de WhatsApp
Meta for Developers → WhatsApp → Configuration → Webhooks

El Webhook URL del bot de WhatsApp apunta al backend en Render (no al nuevo dominio directamente). Si usas un dominio personalizado para el backend, actualízalo. Si sigue usando la URL de Render directamente, no hay nada que cambiar.

✅
El Webhook de WhatsApp apunta a https://contador-ganadero.onrender.com/api/webhooks/whatsapp — eso no cambia con la migración de dominio.
